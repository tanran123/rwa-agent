# 前端

Vue 3 + Vue Router + Vuex + axios。开发服务把 `/api` 代理到 `http://127.0.0.1:8780`。源码都在 `src/`，用 `@` 指向 `src/`。

生成页面前先看根目录 `README.md`。本目录只放页面和调用，不放权重公式，不直接读分类 JSON。

## 目录

| 路径 | 作用 |
| --- | --- |
| `index.html` | 页面壳。 |
| `vite.config.js` | 开发端口、`@` 别名、`/api` 代理。 |
| `src/main.js` | 挂上路由、Vuex 和 axios。 |
| `src/App.vue` | 左侧菜单和页面头。标题「银行Bank return 计算工作平台」。机构、地区、版本、基准日不在顶部筛选，由任务工作台和计量向导各自选择。所有页面都包在这里。未登录时只渲染登录页；登录后侧栏底部显示当前账号和退出。右下角挂 `AgentDock`。 |
| `src/router/index.js` | 路由和导航守卫。`meta.group` 是菜单分组，`meta.sections` 是页内页签，`meta.versionContext` 为真时页面顶部显示 `VersionContext`：完整的版本信息窗口和资本充足率/流动性快捷链接，`meta.public` 是登录页。`/versions/new/workbench` 是新建版本的入口，`/versions/:id/workbench` 是维护工作台，`/tasks/:id` 是任务详情工作台，`/system/*` 是系统管理。未登录访问业务页会跳到 `/login`，无菜单权限的地址回到总览。 |
| `src/utils/nav.js` | 左侧菜单。`规则配置` 只列监管规则版本和机构，其余配置从版本的「监管规则维护工作台」进入；`任务运行` 是任务工作台；`系统管理` 是用户、角色、权限、日志、大模型和 Token 调用。页签不单列菜单项，用 `PARENT` 指回父菜单，配置子页都指回 `/versions`，`/hqla*` 都指回 `/tasks`。`MENU_BY_PATH` 把菜单 id 对到路由，供权限过滤和守卫使用。 |
| `src/utils/auth.js` | 登录会话。`setSession`/`clearSession` 读写本机会话，`can(menuId)` 判断当前账号的菜单权限。会话只保存账号、角色和菜单，不保存密码。 |
| `src/utils/agentCatalog.js` | 对话带给模型的页面、接口和表单。路径和字段跟路由、`src/api` 里已有的名字一致。 |
| `src/store/index.js` | 当前客户、机构、地区、规则版本、基准日。数据来自 `GET /api/bootstrap`。 |
| `src/composables/useContext.js` | 页面读取和修改上面这份上下文。 |
| `src/composables/usePick.js` | 规则列表的勾选、全选和批量删除确认。 |
| `src/composables/useAgentForm.js` | 当前页面把表单和已有的保存登记给右下角对话。 |
| `src/api/request.js` | axios 实例。成功时直接返回响应体。 |
| `src/api/*.js` | 按业务拆开的请求函数。页面只从这里要数据。 |
| `src/view/` | 一个路由一个 `.vue`。按菜单再分子目录。 |
| `src/components/` | 多页共用的抽屉、瀑布、加载、智能体停靠栏、确认框、监管规则版本信息窗口 `VersionContext.vue`、版本信息表单 `VersionInfoForm.vue`、版本两大配置模块 `VersionModules.vue`、页面路径 `PagePath.vue`（规则配置和任务运行子页的面包屑，逐级可点）、规则表单抽屉 `RuleForm.vue`、规则条件编辑器 `WhenEditor.vue`、整份 JSON 文档编辑 `JsonDocEditor.vue`、参数表与名单表格 `RefGridEditor.vue`、敞口划分全景图 `ExposureOverview.vue`、JSON 配置工作台 `JsonConfigWorkbench.vue`、产品组配置向导 `ProductWizard.vue`、三栏字段映射工作台 `FieldMappingWorkbench.vue`。确认框由 `utils/confirm.js` 的 `askConfirm` 打开，不使用浏览器默认确认框。 |
| `src/utils/` | 菜单、规则文案、瀑布布局、版本快捷链接 `ruleLinks.js`、对话排版 `agentText.js`、规则文案翻译 `ruleMap.js`、决策流程布局 `decisionFlow.js`、敞口划分业务分支展示配置 `exposureLanes.js`、字段映射处理步骤定义与执行 `mappingSteps.js`、产品目录展示与指标 `productCatalog.js`。决策图的拖拽跟在 `mermaidStage.js`。 |
| `src/assets/main.css` | 引入 `src/assets/css/` 里的样式。新样式加在那些 css 里，或只写在单个组件上。 |
| `src/assets/mermaid.min.js` | 决策图用的 Mermaid 10.9.1。页面从这里加载，不访问外网。 |

## 写页面时以哪个文件为准

新页面先打开 `src/view/rule/ClausesView.vue`，沿用它的结构：`useContext()`、`AsyncView`、`panel`、`tbl`。表格列只绑定接口已经返回的键。键名到 `server/src/index.js` 里该路由的 `ctx.body` 去核对，不要按数据库列名猜驼峰。

`AsyncView` 只接受 `load`。插槽参数只有 `data` 和 `reload`。加载文案和转圈已经在组件里，页面不要再写一套「正在加载」。

`session` 只有 `store/index.js` 里的那些字段。地区下拉用 `session.jurisdictions` 的 `code` 和 `label`，与条款页相同。

样式只用 `src/assets/css/` 里已有的类，例如 `panel`、`panel-head`、`panel-body`、`tbl`、`compact`、`inline-fields`、`notice`、`danger`、`mono`、`dim`、`clickable`、`sub`。要新类就同时改对应的 css。

## 加一个页面

按这个顺序落文件。每一步都先打开清单里的现有文件再改：

1. `src/view/<分组>/<Name>View.vue`。分组用上面五个目录之一；总览级页面可以放在 `view/` 根下。
2. `src/router/index.js` 增加路由，写上 `meta.group`、`meta.title`、`meta.blurb`。若它是某个菜单下的页签，把 `{ label, path }` 放进对应的 `sections`。
3. 它是新菜单项时，改 `src/utils/nav.js` 的 `NAV`。它只是页签时，改 `PARENT`，不要再加一条菜单。
4. 需要接口时，在 `src/api/<业务>.js` 增加函数，走 `request`。没有合适的业务文件就新建一个，不要把请求写进 `.vue`。
5. 等待数据时用 `components/AsyncView.vue`，加载态是 `<span class="spin">`。空数据和错误分开显示。

页面从 `useContext()` 拿当前地区和版本，不要自己再存一份。模板里可以调用 `Math`、`Number`、`Date`、`Array`、`Object`、`Set`、`JSON`、`Map`。不要在模板里写 `Promise`。

## 智能体停靠栏

`components/AgentDock.vue` 在每一页都在。暴露分类规则按顶栏版本列出。当前版本还没有分类时，页上和监管规则版本列表都可以「创建风险暴露分类规则」，从已有分类复制一份。页签「添加」先复制这一版的通用。除标签为「通用」的页签外，页签上的 × 可以删除。对话先判断是改已有规则还是新增一类。修改先说明当前规则。新增按监管条款从通用分类扩展。用户说全部或按条款库时，先出一版草稿，再由用户调整。确认后再问要不要保存，保存后才画到画布。每个产品的对话单独记在服务端，切换页签或刷新后还在。其他页面把当前路由、这一页的对话，以及 `agentCatalog.js` 里当前页面的接口和表单交给 `sendAgentChat`。返回的 `pages` 是空数组，不用来跳转。返回 `confirm` 为真时，只显示确认和取消，按钮把 `confirm` 真或假送回，输入框停用。回复里的「确认」两个字不会开始计算。返回 `actions` 时，只写入当前页面已登记的表单；`save` 为真才调用这一页已有的保存。删除不在这些步骤里。底稿计算、计量向导、结果明细从左侧菜单进。不要在业务页面里再接一条智能体请求。
