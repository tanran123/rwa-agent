# 权重法风险暴露分类 JSON 怎么写

分类规则在 `knowledge/权重法风险暴露分类.json`。键是英文，界面上显示的中文在 `label`。按这份说明新写一份时，结构照着那份 JSON，不要另起一套键。

## 贴进分类判断页时怎么才保存得上

分类判断页的「编辑流程 JSON」点保存，会先做校验。整份文件顶层必须有 `rules`、`layers`、`categories` 三者之一，或写成 `{ "mode": "ref" }`。都没有时，页面原样报：

```text
未保存。JSON 未通过校验：
1. 需要 layers、categories、rules，或把 mode 设为 ref
```

按本说明生成时，只写带 `rules` 的这一套，不要写成页面逻辑视图。逻辑视图用 `layers`、`if_yes`、`then.risk_weight`，条件比较值放在 `value`。两套键不要混在一份文件里。

生成时用下面这一份骨架。不要另加 `label`、`version`、`description`，也不要另加 `special_rules`。多重评级、同业未评级和缓释都写在 `rules` 里。

```json
{
  "name": "英文标识",
  "title": "中文标题",
  "fields": [],
  "rules": []
}
```

市场风险债券那份被拒，是因为页面当时不认 `rules`。那份里面还有这些不能再写的地方：

- 顶层标题写 `title`，不要写 `label`、`version`、`description`。规则上的说明写 `note`，不要写 `description`。
- 每个字段都要有 `name`、`label`、`meaning`、`source`、`type`。枚举再加 `options`，每项是 `{ "label", "code" }`。不要只留一句 `description`。
- 条件只有 `field`、`op`、`match` 三个键。比较值写在 `match`。不要把比较值写成 `value`。
- 节点上的 `value` 只表示已经确定的风险权重，而且必须是数字。`0.25%` 写成 `0.0025`，`1%` 写成 `0.01`，`8%` 写成 `0.08`。时间档名称、操作说明（例如 `time_band_1`）不能放进 `value`。权重还没定，就不要写 `value`。
- 有 `children` 的节点不写 `value`。
- `rules` 从上到下，第一条命中就停，不再看后面的规则。同一笔要同时做的两段计算，不要写成两条并列的顶层规则，否则第二段永远走不到。放进同一条的 `children`，或拆成两份文件。

`excel`、`extensions`、`remark` 可以后加。`remark` 只给人看，页面和计算都不读。

## 合格多边开发银行的名字写在哪

没有单独的名单区。附件2第四部分那 13 家银行，直接写在规则 `mdb_qualified` 的 `match` 里。巴塞尔委员会更新名单时，只改这一处。

## 文件里有哪几块


| 键            | 作用                                                             |
| ------------ | -------------------------------------------------------------- |
| `fields`     | 分类要使用的字段。大模型用 `label`、`meaning`、`source`、`options` 去对 Excel 列。 |
| `rules`      | 决策树。从上到下，第一条命中就停，再走进它的 `children`。这一层都不中时走 `otherwise`。        |
| `extensions` | 银行自己加的更细分类。挂在已经存在的某条规则下面，不插进 `rules` 中间。                       |
| `excel`      | 大模型写的映射。Excel 表头对到字段 `name`，单元格原文对到 `code`。                    |
| `remark`     | 给改文件的人看的几句说明，程序不用读。                                            |


## 三条写在规则树里

不要写顶层 `special_rules`，也不要另写一份缓释文件。下面三条都是 `rules` 里的节点。`rules` 从上到下第一条命中就停，所以不要把它们写成会和现金、公司、银行抢先命中的并列规则。

市场风险债券、其他产品的规则文件不要加这三条。

条件仍是 `field`、`op`、`match`。权重用比值：20% 写成 `0.2`，50% 写成 `0.5`，100% 写成 `1`，150% 写成 `1.5`。

### 同业未评级债权

写在 `fi_bank`（商业银行风险暴露）的 `children` 最前面，排在第二档、C 级、B 级、A+ 级、A 级之前。`bank_peer_weight` 没填时这两条不命中，继续按资本档次。

在 `fi_bank` 的 `fields` 里加上两个由计算写入的数字字段，`source` 为 `calc`，不要从 Excel 对：

| name | 含义 |
| --- | --- |
| `bank_peer_weight` | 同一银行其他已评级债权里已经算出的最高风险权重。没有其他已评级债权就不要填。 |
| `derived_bank_weight` | 这一笔按资本档次先得出的风险权重。 |

两个子节点：

1. `fi_bank_unrated_peer_150`：`issuer_rating` 等于 `unrated`，且 `bank_peer_weight` 等于 `1.5`。`value` 为 `1.5`。该银行全部未评级债权定为 150%，不限于 3 个月以内。
2. `fi_bank_unrated_short_floor`：`issuer_rating` 等于 `unrated`，`original_maturity_months` 小于等于 `3`，且 `bank_peer_weight` 属于 `0.5` 或 `1`。权重写成：

```json
"weight": { "greater_of": [1, { "field": "derived_bank_weight" }] }
```

这是 100% 与已得权重中的较大者。期限没填或超过 3 个月时不命中。没有其他已评级债权时，不填 `bank_peer_weight`，也不另写一条把权重改成 `0.2`。20% 仍是资本档次里已有的末端，例如 A+ 级且原始期限不超过 3 个月。30%、40%、75% 不触发上面两条。

### 多重评级

`name` 为 `multiple_assessments`，放进 `rules` 数组，和其他风险暴露并列，但不要写 `when`。没有 `when` 时，分类不会停在这一条，也不会挡住前面的现金、主权、银行。

`applies_to` 只放 `issuer_rating`、`bond_rating`、`country_rating`。商业银行的 A+、A、B、C 不写在这里，仍由商业银行那一支决定。

`pick` 和 `children` 都写。`children` 是树上的三档。`when.field` 固定为 `assessment_count`。`use` 只用下面三个词：

| 个数 | op | match | use | 子节点 name |
| --- | --- | --- | --- | --- |
| 1 个 | `eq` | `1` | `only` | `multiple_assessments_one` |
| 2 个且权重不同 | `eq` | `2` | `higher_weight` | `multiple_assessments_two` |
| 3 个及以上且权重不同 | `gte` | `3` | `higher_of_two_lowest_weights` | `multiple_assessments_many` |

权重相同就用这个相同的权重。对不上数字权重的评级不计入个数，也不另补一个权重。不得为了降低资本要求改选评级。

### 缓释

`name` 为 `crm_split`，同样放进 `rules`。父节点不要写 `when`，权重分类不进入这一条。原债务人的权重保持前面规则已经得出的结果。

父节点写 `formula`：`covered_amount * protection_weight_used + uncovered_amount * debtor_weight`。`covered.floor` 为 `0.2`。字段与普通字段相同，要有 `name`、`label`、`meaning`、`source`、`type`，枚举再加 `options`。

| name | 作用 |
| --- | --- |
| `covered_amount` | 被覆盖金额。货币错配时先折扣再填。 |
| `uncovered_amount` | 未覆盖金额。 |
| `protection_weight` | 抵押品或担保人的风险权重。 |
| `debtor_weight` | 原债务人已经确定的权重。`source` 写 `calc`。拆分时原样使用。 |
| `same_currency` | 同币种 `yes`，不同 `no`。 |
| `collateral_kind` | `cash_deposit` 现金存款，`sovereign_debt` 极优质主权债，`other` 其他。 |
| `sovereign_market_haircut` | 主权债市值已经按八折计入时填 `0.8`。 |

`children` 两条：

1. `crm_currency_mismatch`：`same_currency` 等于 `no` 时，`collateral_value_factor` 为 `0.5`。抵押品价值乘 0.5 后再算覆盖金额。
2. `crm_zero_exemption`：同币种，且 `collateral_kind` 属于 `cash_deposit` 或 `sovereign_debt`。主权债还要 `sovereign_market_haircut` 等于 `0.8`，写在 `if_collateral_kind.requires`。满足时 `value` 为 `0`，不再套 0.2 下限。现金存款不要求八折。

`covered_amount`、`uncovered_amount`、`protection_weight`、`same_currency`、`collateral_kind` 缺任何一项时，不拆分、不计算。


决策图上每个绿框是 `rules` 里的一条。它的细分写在 `children`，`children` 里面还可以再写 `children`。先命中外层，再进内层。

`value` 是已经确定的风险权重，必须是数字。10% 写成 `0.1`，100% 写成 `1`，150% 写成 `1.5`。不要写成 `"10%"`，也不要写成档位名称或其他字符串。有 `children` 的节点不写 `value`。

权重还要向别处取数时，不写 `value`，写 `weight`。

按交易对手计量：

```json
"weight": { "same_as": "counterparty_ordinary_claim" }
```

`counterparty_ordinary_claim` 是该交易对手做一笔普通债权时的风险权重。分类已经知道这笔是居住用房地产、商用房地产、已违约或合格资产担保债券之后，权重不在这里定死，而是忘掉这个产品类别，只看交易对手是谁，从 `rules` 最外层再分一次。公司走公司，个人走个人，银行走商业银行。用那一次得到的 `value`。只分这一次，不会回到当前这条。

例如第二档银行的居住用房地产：命中之后不再看贷款价值比，权重等于这个债务人如果借的是普通贷款时的权重。

和交易对手权重比大小：

```json
"weight": {
  "greater_of": [
    0.9,
    { "same_as": "counterparty_ordinary_claim" }
  ]
}
```

`greater_of` 里每一项都是一个权重，取最大的。数字 `0.9` 就是 90%。上面这个写法用在商用房地产「依赖现金流且贷款价值比高于 60%、不超过 80%」：90% 和交易对手普通债权权重哪个大，用哪个。和本笔已经算出的权重比大小时，把数字和一个字段放在一起，例如 `{ "greater_of": [1, { "field": "derived_bank_weight" }] }`。

还要按评级、贷款价值比或人工选定级别分成几档时，继续写 `children`，不要写进 `weight`。某一档的权重定了，再在那一档上写 `value` 或 `weight`。

## 字段

规则里的 `field` 写字段 `name`，不写 Excel 表头。表头每次上传都可能变，由大模型对进 `excel`。

每个字段有这几项：


| 键         | 作用                                                                                  |
| --------- | ----------------------------------------------------------------------------------- |
| `name`    | 英文，整份文件不重复。规则和 `excel.field` 都写它。                                                   |
| `label`   | 中文名。大模型用它和表头比对。                                                                     |
| `meaning` | 这个数或这个是否在业务上指什么、单位是什么、容易和哪一列搞混。大模型主要读这一段。                                           |
| `source`  | `column` 是表里应有一列或可由几列算出。`calc` 通常不是现成的一列，要在映射的 `how` 里写算法。`manual` 由人填，不要从 Excel 对。 |
| `type`    | `enum`、`list`、`number`、`string`。                                                    |
| `options` | 枚举的可选取值。`label` 是中文，`code` 是规则里的 `match`。                                           |
| `unit`    | 数字的单位。`ratio` 是比值，`CNY` 是元，`month` 是月。                                              |


是否类也是 `enum`，选项固定为「是」`yes`、「否」`no`。`match` 写 `yes` 或 `no`，不要写 `true`、`false`。`list` 用 `contains`。百分比用比值，金额用元。字段没有填时，引用它的条件不命中。

顶层 `fields` 是每一笔都可能用到的。某一类自己的字段写在那条规则的 `fields` 里，同样要有 `meaning` 和 `source`，大模型也要对。

## Excel 列怎么对上这些字段

大模型只改 `excel`，不改 `rules`。读每个字段的 `label`、`meaning`、`source`、`options`，再读 Excel 表头和几行样例。

`source` 为 `manual` 的字段跳过，例如本行档次 `bank_tier`、审慎判断 `prudent`、人工选定的 B 或 C。

对得上时追加一条：

```json
{
  "field": "counterparty_type",
  "columns": ["客户类型"],
  "values": { "财政部": "cn_central_government", "一般企业": "corporate" }
}
```

- `field`：字段 `name`。
- `columns`：Excel 表头，用表里的原文。
- `values`：单元格原文到 `code`。只用于枚举和列表。值必须是 `options` 里的 `code`，不能写中文。
- `how`：一个字段来自多列，或要换单位时才写。例如贷款余额除以押品价值，百分比要换成比值。

数字字段不写 `values`。50% 若在表里是 `50`，在 `how` 里写「除以 100」。

对不上的字段不要硬填。没映射到的字段视为没填，引用它的条件不命中。

`excel` 里标了 `example: true` 的是样子，可以删。

## 一条规则怎么写

```json
{
  "name": "fi_bank",
  "label": "商业银行风险暴露",
  "when": {
    "all": [
      { "field": "counterparty_type", "op": "eq", "match": "commercial_bank" }
    ]
  },
  "children": []
}
```

- `name`：英文，文件内不重复。`extensions` 的 `attach_to` 填这个名字。
- `label`：中文分类名。决策图绿框和附件2里有的，用原文，不要另起简称。
- `when.all`：里面每一条都要成立。
- `when.any`：里面成立一条即可。`all` 和 `any` 可以互相嵌套。
- `children`：命中本条之后继续分。里面只放带 `when` 的分支。
- `otherwise`：这一层适用的 `when` 都不成立时走这里。它和 `children` 平级，不再写 `when`。它自己还可以再有 `children` 和 `otherwise`。
- `skip`：本产品不适用这条时整段跳过。`skip` 成立就当没有这条，子级也不进。被跳过的那条 `when` 本来会命中时，不再走同一层的 `otherwise`，退回外层继续下一条。字段没填视为适用。
- `fields`：只给这一条和它下面的子类用的输入。新字段同样写 `meaning` 和 `source`，大模型才会去对 Excel。字段 `name` 在整份文件里不重复。
- `value`：已经确定的风险权重，必须是数字。10% 写成 `0.1`。条件的比较值写在 `match`，不要写在 `value`。权重还没定、或结果不是一个权重时，不要写 `value`。
- `weight`：权重向别处取。`same_as` 为 `counterparty_ordinary_claim` 时，用该交易对手普通债权的权重。`greater_of` 里放几个权重，取最大的。有 `weight` 就不要再写 `value`。
- `note`：给人看的备注。权重依据写在这里。

贷款不能贷给银行时，在商业银行那条上写：

```json
"fields": [
  {
    "name": "fi_bank_applicable",
    "label": "是否适用",
    "type": "enum",
    "options": [
      { "label": "适用", "code": "applicable" },
      { "label": "不适用", "code": "not_applicable" }
    ]
  }
],
"skip": { "field": "fi_bank_applicable", "op": "eq", "match": "not_applicable" }
```

产品把 `fi_bank_applicable` 填成 `not_applicable` 后，商业银行及其下级都不再判断。交易对手即使是银行，也不会落到同一层的「其他金融机构」，而是回到外层，继续看房地产、公司、个人。

条件固定是这三个键：

```json
{ "field": "字段的 name", "op": "eq", "match": "比较值" }
```

`op` 可以用：


| op                    | 含义              | match 怎么写              |
| --------------------- | --------------- | ---------------------- |
| `eq`                  | 等于              | 一个值                    |
| `in`                  | 是其中任意一个         | 数组                     |
| `contains`            | 多选字段里含有这一项      | 一个值，用于 `property_uses` |
| `gt` `gte` `lt` `lte` | 大于、大于等于、小于、小于等于 | 数字                     |


枚举的可选值写在字段的 `options` 里。规则的 `match` 写 `code`，不写中文 `label`。百分比用比值，金额用元。字段没有填时，引用它的条件不命中。

## 自己加一层小类

抄 `extensions` 里的样子。`attach_to` 填已经命中的那条规则的 `name`。这一层大家都要用的字段，写在扩展自己的 `fields` 里。某一个子类自己用来判断或计算的字段，写在那个子类的 `fields` 里，不要和兄弟子类共用。

```json
{
  "example": true,
  "attach_to": "corporate_general",
  "fields": [
    {
      "name": "product_name",
      "label": "产品",
      "type": "enum",
      "extensible": true,
      "options": [
        { "label": "贸易融资", "code": "trade_finance" }
      ]
    }
  ],
  "children": [
    {
      "name": "product_trade_finance",
      "label": "贸易融资",
      "when": { "all": [{ "field": "product_name", "op": "eq", "match": "trade_finance" }] },
      "fields": [
        {
          "name": "sight_lc",
          "label": "是否即期信用证",
          "type": "enum",
          "options": [
            { "label": "是", "code": "yes" },
            { "label": "否", "code": "no" }
          ]
        }
      ],
      "children": [
        {
          "name": "tf_sight_lc",
          "label": "即期信用证",
          "when": { "all": [{ "field": "sight_lc", "op": "eq", "match": "yes" }] }
        }
      ]
    }
  ]
}
```

`example: true` 的两条是例子，可以删。扩展不能把已经归进「已违约风险暴露」的一笔改成公司，也不能调换 `rules` 的先后。

## 字段说明

下面是各字段在分类里怎么用。大模型对 Excel 时以 JSON 里的 `meaning` 为准，那里写了单位、粒度和容易混淆的列。

### 工具和违约


| name                      | 中文                | 含义                                                                   |
| ------------------------- | ----------------- | -------------------------------------------------------------------- |
| `instrument_type`         | 工具                | `equity` 股权，`covered_bond` 资产担保债券，`claim` 债权。                        |
| `treat_as_equity`         | 是否应视同股权           | 附件2第九部分。收益主要靠资本利得、不可赎回、有剩余索取权，或与一级资本同样结构，或约定用股票清偿。监管已认可按债务处理的填 `no`。 |
| `state_subsidized_equity` | 是否国家重大补贴并受政府监督的股权 | 中央财政持股，方案写明规模、范围、运作和风险，并经国务院批准。                                      |
| `is_defaulted`            | 是否已违约             | 逾期超过 90 天，或不处置押品就可能无法全额偿还。自然人按这一笔填，其他按这个债务人填。                        |
| `is_subordinated`         | 是否次级债权            | 金融机构风险暴露不含次级债权。                                                      |




### 合格资产担保债券


| name                    | 中文                  | 含义                          |
| ----------------------- | ------------------- | --------------------------- |
| `covered_pool_eligible` | 资产池是否只含合格资产         | 池内资产限于附件2第十部分列出的那几类。        |
| `covered_oc_ratio`      | 资产池名义价值 / 未偿还债券名义价值 | 110% 写成 `1.1`。合格要求不低于 110%。 |
| `covered_disclosure_ok` | 是否至少每半年能取得披露信息      | 附件2第十部分要求的资产池和债券披露。         |




### 交易对手

### 商业银行评级

这些用来把商业银行分成附件2的 A+、A、B、C，以及权重表里的第二档和短期。


| name                       | 中文           | 含义                                                                                                           |
| -------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------ |
| `meets_minimum_capital`    | 是否满足最低资本要求   | `yes`、`no`、`unknown`。无法判断时划为 C 级。不含第二支柱。                                                                     |
| `meets_other_capital`      | 是否满足其他各级资本要求 | 储备资本、逆周期资本、系统重要性附加资本。无法判断时为 B 级或 C 级，要人工选。                                                                   |
| `cet1_ratio`               | 核心一级资本充足率    | 14% 写成 `0.14`。A+ 要求不低于 14%。                                                                                  |
| `leverage_ratio`           | 杠杆率          | 5% 写成 `0.05`。A+ 要求不低于 5%。                                                                                    |
| `audit_opinion`            | 外部审计意见       | `none` 无报告，`unqualified` 无保留，`qualified` 保留，`adverse` 否定，`disclaimer` 无法表示，`going_concern` 持续经营存疑。后三种划为 C 级。 |
| `bank_tier`                | 银行档次         | `tier1` 第一档，`tier2` 第二档。这是权重表的分档，不是附件2的分类名。                                                                  |
| `original_maturity_months` | 原始期限         | 单位月。3 个月以内走短期权重。                                                                                             |
| `cross_border_trade`       | 是否跨境货物贸易     | 填 `yes` 且原始期限不超过 6 个月时，与 3 个月以内同一档短期权重。                                                                      |
| `issuer_rating`            | 外部评级         | 境外主权、其他中央银行、其他多边开发银行使用。分档写在对应规则的 `children` 里。                                                               |

| name                                 | 中文                 | 含义                                                                     |
| ------------------------------------ | ------------------ | ---------------------------------------------------------------------- |
| `operating_normal`                   | 经营正常且按时披露          | 经营正常、无风险迹象、按时披露财务报告。                                                   |
| `no_major_violation_3y`              | 最近三年无重大违法违规        |                                                                        |
| `not_on_dishonest_list`              | 未进失信名单             | 未纳入人民法院失信被执行人名单。                                                       |
| `no_false_statements`                | 财报没有虚假记载           |                                                                        |
| `annual_audit_opinion`               | 最新年报审计意见           | 投资级要求 `unqualified`（无保留）。另有保留、否定、无法表示、无报告。                             |
| `no_default_3y`                      | 最近三年没有违约或拖欠        |                                                                        |
| `loan_classification_normal`         | 本行分类均为正常           | 本行对其债权的风险分类都是正常。                                                       |

| `profit_tests_met`                   | 盈利条件都满足            | 近三年合并利润总额和归属母公司净利润都大于 3000 万；法人利润总额和净利润都大于 0；最新一期两边净利润都大于 0；综合收益都大于 0。 |

| `no_other_material_risk`             | 没有其他重大风险           | 银行认为存在其他重大风险时填 `no`。                                                   |
